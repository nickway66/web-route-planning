# WEBMAP_VS 产品文档

本文档用于帮助后续 AI 或产品/开发人员快速理解产品目标、功能边界、核心用户流程和交互约束，避免每次迭代都重新阅读全部项目文件。

## 1. 产品定位

WEBMAP_VS / VOYAGE 是一个面向自由行路线规划的 PC Web 工具。

它要解决的问题是：用户在规划旅行时，经常需要在攻略、地图、不同地点间多出行方式规划、截图导出、历史保存之间来回切换。本产品将“找地点、排顺序、看真实路线、管理多条方案、保存/导出成果”集中在一个地图界面中完成。

产品关键词：
- 自由行路线规划
- 多图层路线管理
- 不同地点间多出行方式选择
- AI 生成和修订路线
- 本地保存和导出

## 2. 目标用户

- 自由行用户：出发前整理景点、酒店、交通枢纽、餐饮点位。
- 攻略型用户：需要比较多条路线、按天拆分路线、减少绕路。
- 学生、上班族、家庭出游用户：希望低门槛完成路线规划，不想做攻略。
- 演示/作品集场景：强调地图可视化、AI 路线、导入导出、本地缓存等完整体验。

## 3. 典型使用场景

### 场景 1：手动规划一条旅行路线

用户搜索多个景点，设置起点、终点、途经点，选择驾车/步行/公交/骑行等方式，生成真实路线，并在地图上查看。

### 场景 2：AI 一键生成路线

用户输入：

```text
生成一条深圳一日游路线，我想去桔钓沙
```

系统返回自然语言行程，并展示“是/否”按钮。用户点“是”后，系统把 AI 推荐地点转换为高德 POI 和真实地图路线。

### 场景 3：按天或多方案管理路线

用户规划多天行程，每天生成一个图层。每个图层可以独立显示、隐藏、改名、编辑、删除和导出。

### 场景 4：导出和分享路线成果

用户勾选需要导出的路线，导出 JSON、GPX、PNG 或 PDF，用于分享、存档或后续导入。

## 4. 核心用户流程

### 4.1 地图浏览与搜索

1. 页面加载后初始化高德地图。
2. 默认显示中国视角。
3. 用户可以缩放、拖拽地图。
4. 用户可以切换白天/夜间主题。
5. 顶部搜索框输入关键词，2 个字符以上触发搜索推荐。
6. 点击搜索或按回车后调用后端 POI 搜索。
7. 搜索结果展示在地图上方浮层，并在地图上打点。
8. 搜索结果可执行：
   - 定位到地图
   - 设为起点
   - 设为终点
   - 添加为途经点

搜索结果优先考虑当前地图视窗。无结果时允许扩展范围，并通过 toast 告知用户。

### 4.2 手动路线规划

1. 用户点击左侧路线管理区的“+”。
2. 右侧打开新路线编辑器。
3. 用户设置起点、终点和途经点。
4. 点位来源包括搜索结果和地图点选。
5. 用户选择全段默认出行方式，也可逐段设置：
   - 驾车
   - 步行
   - 公共交通
   - 骑行
6. 公共交通需要公交规划城市，系统会尝试从起点城市反推。
7. 用户点击“生成新路线”。
8. 系统调用后端 `/api/routes/plan`。
9. 成功后创建新图层，在地图上绘制路线。

### 4.3 路线编辑

用户选中左侧图层后，右侧打开路线编辑器。

可编辑内容：
- 路线名称
- 备注
- 点位顺序
- 分段交通方式
- 子路线显示/隐藏

可执行操作：
- 点击点位定位地图
- 拖拽排序点位
- 删除点位，但至少保留两个点
- 用地图点选替换点位
- 在两个点之间插入途经点
- 点击“应用修改并重算路线”
- 撤销/重做

重算成功后，路线会自动保存到本地缓存。

### 4.4 AI 聊天生成路线

1. 用户打开 AI 路线助手。
2. 用户输入自然语言需求。
3. 前端将最近聊天消息发送到 `/api/ai/chat`。
4. 后端请求智谱模型，要求返回固定 JSON envelope。
5. 后端解析 `route_plan`，并用 plan 生成用户可读的详细行程。
6. 前端只展示自然语言，不展示 JSON。
7. 如果 plan 中有至少两个地点，气泡下方显示“是/否”路线添加按钮。
8. 用户点击“是”。
9. 前端调用 `/api/routes/ai-build`。
10. 后端搜索 POI、优化顺序、规划真实路线、生成图层。
11. 成功后路线加入地图，聊天消息状态变为“已添加到地图”。
12. 失败后保留重试入口并显示错误通知。

### 4.5 AI 路线修订

当最近对话已有路线规划上下文时，用户可以继续说：

```text
我想去桔钓沙
加上世界之窗
换成亲子路线
第一站去莲花山公园
不要太远
```

系统行为：
- 后端识别这是路线修订，而不是普通景点咨询。
- 如果模型第一次返回普通聊天或旅游建议，后端会用更严格的 route_plan prompt 重试。
- 如果重试仍失败，后端会根据上一条路线和新偏好重建一个可用 route_plan。
- 前端继续显示详细路线和“是/否”添加到地图按钮。

### 4.6 导入导出

路线导出：
- JSON
- GPX
- PNG 地图截图
- PDF 地图截图

导出规则：
- 左侧“分享”只导出已勾选路线。
- 未勾选时提示至少选择一条。
- JSON/GPX 由后端生成。
- PNG/PDF 由前端截图地图区域生成。
- 导出截图前会隐藏搜索框、面板和高德控件，自动 fit 到路线范围，导出后恢复原视角。

导入：
- 当前完整支持 JSON 图层数组导入。
- GPX 导入会提示当前环境暂不支持直接解析渲染。
- AI 对话支持 JSON 导入导出。

### 4.7 历史与会话

路线历史：
- 保存在 localStorage。
- 支持查看详情。
- 支持地图预览。
- 支持加载到当前地图继续编辑。
- 支持删除。

AI 会话：
- 使用 IndexedDB。
- IndexedDB 不可用时降级到内存。
- 当前会话 ID 存 localStorage。
- 支持新建、选择、重命名、删除、清空当前、清空全部、导入、导出。

## 7. AI 路线助手行为规范

### 用户输入类型

明确路线请求：

```text
生成一条深圳一日游路线
帮我规划成都三日游
给我一条广州两日旅游路线，至少五个地点
```

偏好约束：

```text
亲子路线
轻松一点
不要太远
夜游路线
```

路线修订：

```text
我想去桔钓沙
加上世界之窗
第一站去莲花山公园
```

普通咨询：

```text
桔钓沙适合什么时候去
深圳有哪些适合亲子的景点
```

### 系统返回类型

- `chat`：普通聊天，只展示自然语言。
- `travel_advice`：旅游建议，但不足以落图，不显示添加地图按钮。
- `route_plan`：可落图路线，必须包含 plan。
- `cancel_or_negative`：取消/拒绝，清除 pending/failed 路线动作。

### 添加地图按钮出现条件

只有满足以下条件时出现：
- assistant 消息包含有效 route_plan。
- 前端从 plan 中提取到至少两个地点。
- 消息状态是 pending 或 failed。

按钮行为：
- 点“是”：开始将 AI 路线添加到地图。
- 点“否”：拒绝该次路线添加。
- processing/accepted/rejected 后按钮禁用。

### JSON 防泄露规则

用户永远不应该看到：
- JSON 代码块标记
- `"type":"route_plan"`
- 完整 JSON envelope
- 裸 `{...}` 结构化数据

用户应该看到：
- 自然语言路线摘要。
- 具体地点。
- 游玩时长。
- 费用。
- 营业时间。
- 简介。
- 是否添加到地图的按钮。

## 8. 非目标、限制与风险

### 非目标

- 不做机票、酒店、门票预订。
- 不做支付。
- 不做账号体系。
- 不做云同步协作。
- 不做完整 GIS 专业编辑器。

### 依赖风险

- 高度依赖高德：JS 地图、POI、路线规划、AutoComplete、逆地理编码、Web Service 都依赖高德 Key 和额度。
- 高德 QPS 风险：AI 多地点建图可能触发限流。后端已有固定间隔和 backoff，但不能完全避免。
- 依赖智谱/LLM：AI 输出质量、地点标准化、JSON 合法性和响应时间不可完全控。

### 产品风险

- AI 地点误选：同名地点可能命中外地 POI，当前通过城市、地址、距离和锚点评分降低误选。
- 本地数据丢失：路线和会话主要在浏览器本地，换设备或清缓存会丢失。
- 截图导出受浏览器、高德渲染、canvas 和跨域资源影响。
- 公共交通规划依赖城市参数，跨城或城市识别错误时可能失败。
- 路线编辑后需要手动重算，不是所有编辑都会实时更新地图路线。
- GPX 导入未完整实现。
