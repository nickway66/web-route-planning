# 强制登录入口与注册可用性设计

## 目标

未登录访客打开网站时，立即显示现有样式的登录卡片和遮罩层；只有成功登录或注册并登录后，才能使用地图和路线功能。注册不包含邮箱验证，仅校验邮箱格式与至少 8 位密码，并将用户真实写入 SQLite 数据库。

## 体验与状态

- 应用初始化时读取认证状态；未认证则自动进入 `login` 状态并渲染现有登录卡片。
- 强制登录状态下不渲染关闭按钮，也不允许 Escape、点击遮罩或其他页面操作绕过认证。
- 登录卡片保留“去注册 / 去登录”切换；注册成功后自动调用登录接口并解除遮罩。
- 已认证用户的现有地图、路线工作区和云端会话行为不变。
- 认证请求失败时，界面保留当前输入，显示可操作的中文错误。网络不可达时统一显示“无法连接认证服务，请确认后端已启动”。

## 注册与认证契约

- `POST /api/auth/register` 接收 `email` 和 `password`；邮箱使用现有 Pydantic 邮箱格式验证，密码长度改为 8–128 位。
- 注册成功后后端继续使用现有 SQLite、密码哈希及唯一邮箱约束创建用户；重复邮箱返回 409。
- 前端表单的 `minlength`、提示文案和后端 `RegisterRequest`、`LoginRequest` 统一为 8 位最小长度，避免前后端规则不一致。
- 不增加邮箱验证码、邮件发送、找回密码或额外身份信息。

## 网络可用性

- 前端继续通过 `VITE_BACKEND_BASE_URL` 调用 FastAPI；开发与部署说明明确要求启动后端，并配置可访问的 API 地址。
- API 请求在 `fetch` 抛出网络错误时包装为中文连接错误；HTTP 4xx/5xx 仍显示后端返回的 `detail`。
- FastAPI 的既有 CORS 配置继续由 `CORS_ORIGINS` 控制；测试覆盖开发前端源可访问认证端点的配置。

## 测试与验收

- 前端静态/行为测试：未登录初始化打开强制登录卡片、无关闭绕过、登录和注册切换、密码最小长度 8、网络错误文案。
- 后端 API 测试：8 位密码可注册和登录，7 位密码被拒绝，邮箱格式与重复邮箱仍被拒绝。
- 手工验收：启动前后端后，首次打开页面不能操作地图；输入有效邮箱和 8 位以上密码注册后自动登录并可进入地图；刷新后可使用同一账号登录。

## 非目标

- 邮箱验证、密码找回、第三方登录、匿名访问与重新设计登录视觉不在本次范围内。
